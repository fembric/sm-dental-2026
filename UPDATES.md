# Как обновлять сайт

Рабочая папка: `sm-dental-github`. Редактируйте исходники здесь, а не dist и не прежнюю копию sm-dental.

## Один раз на компьютере

Нужны Git for Windows и Node.js 22 LTS (с npm) в PATH. Выполните в папке проекта, подставив свои данные:

```powershell
git config user.name "Ваше имя"
git config user.email "Ваш email или noreply-адрес из GitHub Settings → Emails"
```

При запросе GitHub завершите вход через браузер. Токены не сохраняйте в файлах проекта.

## После изменения сайта

Дважды нажмите **publish.cmd** или выполните:

```powershell
npm run publish -- "Краткое описание изменения"
```

Скрипт проверит ветку и адрес репозитория, новые изменения на GitHub, состав файлов и распространённые признаки секретов. Затем соберёт и проверит сайт, сохранит изменения в Git и отправит main. При ошибке остановится. Проверка секретов эвристическая: не помещайте личные данные, заявки и ключи в исходники.

После отправки GitHub Actions автоматически публикует dist. Откройте https://github.com/fembric/sm-dental-2026/actions и дождитесь зелёного результата последнего запуска. Успешный push ещё не означает успешную публикацию. Адрес сайта: https://fembric.github.io/sm-dental-2026/.

Если GitHub Pages ещё не включён: Settings → Pages → Source → GitHub Actions, затем Actions → Publish GitHub Pages → Run workflow.

Если на GitHub появились чужие изменения, скрипт остановится. Не используйте force push: сначала согласуйте изменения. Повторный запуск после ошибки отправки отправит уже сохранённый коммит.

Автоматически отправлять каждое сохранение файла не рекомендуется: так на сайт могут попасть незавершённые правки. Здесь достаточно одного запуска после готовой доработки; сборка и публикация дальше выполняются автоматически. В GitHub Settings → Notifications можно включить уведомления Actions об ошибках запусков.
